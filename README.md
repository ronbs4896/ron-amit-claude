# ron-amit-claude

דף נחיתה לקורס הדיגיטלי של עמית ליטמן: בניית סוכן AI לשירות לקוחות בוואטסאפ ובאינסטגרם.
249 ש״ח + מע״מ במקום 997.

הכל נמצא בקובץ אחד: `index.html`. אין תלויות ואין שלב build, פשוט פותחים אותו בדפדפן או מעלים לאירוח.

## מה צריך לערוך לפני שמעלים

### 1. בלוק ההגדרות (בתחתית הקובץ, בתוך `<script>`)

```js
const CONFIG = {
    CHECKOUT_URL: '#',                       // קישור התשלום. חובה.
    DEADLINE: '2026-09-01T23:59:00+03:00',   // מתי מחיר ההשקה נסגר
    HERO_VIDEO: '',                          // יוטיוב / וימאו / mp4. ריק = הנגן לא לחיץ
    TESTIMONIAL_VIDEOS: ['', '', '', ''],    // סרטוני עדויות לפי סדר הכרטיסים
    SHOW_LIVE_SOCIAL: true,                  // "17 צופים עכשיו" + פופאפ רכישות
};
```

`CHECKOUT_URL` — כבר מחווט ללינק Morning. כל כפתורי ה-CTA פותחים **פופ-אפ
הרשמה** (שם, טלפון, מייל, אישור תקנון — הכל חובה), ורק טופס תקין ממשיך
לדף התשלום. `LEAD_WEBHOOK_URL` — מחווט ל-Webhook של Make שמזרים לרב מסר
(ראה סעיף "רב מסר" למטה); ריק = הליד נשמר רק ב-localStorage.
אצל ספק הסליקה יש להגדיר את `thanks.html` ככתובת ההצלחה (success redirect).

`SHOW_LIVE_SOCIAL` שולט על מונה הצופים ("17 צופים עכשיו") ועל מונה הכרטיסים
היורד. פופ-אפ הרכישות הוסר. `false` מכבה את שניהם.

### 3. מקומות שמסומנים ב-`✏️` בקוד

חפש `✏️` בקובץ. כל מופע מסמן טקסט או תמונה שצריך להחליף בתוכן אמיתי,
בעיקר בסקשן של עמית ובכרטיסי הדוגמה של הוואטסאפ.

## צבעים ורצועות

הרקעים אחידים, בלי גרדיאנטים. כל סקשן הוא רצועה בצבע מלא, ושתי רצועות מתחלפות
לסירוגין עם קו דק ביניהן, כדי שהחלוקה בין הסקשנים תהיה ברורה.

```css
--bg:      #0c1a23;   /* רצועה בסיסית */
--bg-alt:  #112935;   /* רצועה מתחלפת */
--bg-deep: #070f15;   /* סרגל עליון, כרטיס המחיר, פוטר */
--bg-card: #17303d;   /* כרטיסים */
```

בפועל: `<section class="section band">` או `class="section band-alt">`.
כדי לחזק או להחליש את ההפרדה, מספיק לשנות את `--bg-alt` ואת `--line`.
מעל כל סקשן יש תווית קטנה (`.eyebrow`) שמסמנת את הנושא.

## תגיות (Badges)

גיאומטריה אחת לכל התגיות בדף, והווריאנט קובע רק צבע:
`padding: 6px 14px`, `radius: 999px`, `12.5px/700`, מסגרת 1px.

```html
<span class="badge badge-success"><span class="b-dot"></span>טקסט</span>
```

| ווריאנט | מתי משתמשים |
|---|---|
| `badge-primary` | מילוי ירוק מלא. הדגשה יחידה במסך, לא יותר מאחת |
| `badge-secondary` | תווית ניטרלית בלי משמעות סטטוס |
| `badge-outline` | תווית שקטה. זה מה שה-`eyebrow` מעל כל סקשן משתמש בו |
| `badge-destructive` | אזהרה, אובדן, מה שהמשתמש מפסיד |
| `badge-success` | תוצאה חיובית, מה שהסוכן השיג |
| `badge-warning` | מחסור וזמן שנגמר |
| `badge-info` | מידע ניטרלי, בלי צבע רגשי |

גדלים: `badge-sm` (10.5px) ו-`badge-lg` (13px). נקודת סטטוס: `<span class="b-dot">`,
יורשת את צבע הטקסט. `pulse-dot` נשארת אדומה בכוונה גם בתוך תגית ירוקה, כי היא
מסמנת דחיפות ולא סטטוס.

על רקע כהה הווריאנטים הם **טונאליים** (מילוי שקוף על הרקע) ולא צבע רווי מלא,
שגורם לזוהר. היוצא מן הכלל הוא `badge-primary` ותגית המחיר בזהב, שתיהן עוגן
ויזואלי מכוון. כל שבעת הווריאנטים נבדקו מול ארבעת צבעי הרצועות ועוברים
WCAG AA לטקסט קטן, הנמוך ביותר 5.97:1.

## דף התודה (`thanks.html`)

דף קצר לאחר תשלום: אישור ושלושת הצעדים הבאים. הגישה לקורס מגיעה במייל.
הסימולטור האינטראקטיבי עבר לדף המכירה, לסקשן ההדגמה, והחליף שם את
סליידר כרטיסי הצ'אט.

בתחתית הקובץ יש `CONFIG` משלו:
- `COURSE_URL` — לאן מוביל "פתח את השיעור הראשון". חובה לפני עלייה לאוויר.
- `WHATSAPP_GROUP_URL` — קבוצת תלמידים. ריק = השורה לא מוצגת.

## תקנון

התקנון יושב במודאל בדף הראשי (נפתח מהפוטר ומהצ'קבוקס שבפופ-אפ), עם פרטי

כדי שלא תסתור את התקנון. זו טיוטה, לא ייעוץ משפטי — חובה עו״ד לפני פרסום.

## הפונט

Birzia כבר נמצא בריפו בארבעה משקלים, בשני פורמטים: `woff2` לכל דפדפן מודרני
ו-`woff` כגיבוי. הקבצים חייבים להישאר **ליד `index.html`**, בשמות שלהם.

```
Birzia-Light.woff2 / .woff     משקל 300
Birzia-Medium.woff2 / .woff    משקל 400-500
Birzia-Bold.woff2 / .woff      משקל 600-700
Birzia-Black.woff2 / .woff     משקל 800-900
```

לכל `@font-face` יש גם `local()`, כלומר מי שהפונט מותקן אצלו במחשב יראה אותו
בלי להוריד כלום. הדף טוען מראש את משקל 900, שהוא הנפוץ ביותר, כדי שלא יהיה
הבזק של Heebo בטעינה.

**אם פותחים את הקובץ בלחיצה כפולה** (כתובת `file://`) הקונסול יראה שגיאת CORS
על ה-preload. זה מגבלה של הפרוטוקול ולא באג, והפונט עצמו נטען כרגיל. בשרת
אמיתי זה נקי, ובדקתי שאין הורדה כפולה.

**רישוי:** רישיון דסקטופ בדרך כלל לא מתיר הטמעה באתר. שווה לוודא מול מי
שקנית שיש כיסוי לשימוש ווב לפני שזה עולה לאוויר.

## המספרים שבדף

החישוב בכל הדף אחיד ומבוסס על 40 ש״ח לשעה:

- עובד במשרה מלאה: 40 × 8 שעות × 22 ימים = **7,040 ש״ח בחודש**, כלומר 84,480 בשנה
- כיסוי 24/7 דורש 4 עובדים במשמרות = **28,160 ש״ח בחודש**
- הסוכן: 3 ש״ח ליום = **כ-90 ש״ח בחודש**
- החיסכון בשנה הראשונה מול עובד אחד: **83,400 ש״ח**

גובה העמודות בגרף ההשוואה נגזר מהמספרים האלה (`--h` על כל `.gc-col`, כש-28,160 = 85%).
אם משנים מספר, צריך לעדכן גם את ה-`--h` המתאים.

## רב מסר (לידים ורוכשים)

שני הדפים שולחים ל-`/api/lead`, פונקציית Serverless שרצה על Vercel מתוך
`api/lead.js`:

- דף המכירה, אחרי מילוי תקין של פופ-אפ ההרשמה: `stage: "lead"` ← רשימת ה-hotlist
- דף התודה, פעם אחת לדפדפן: `stage: "purchase"` ← רשימת הרוכשים, **ומחיקה מה-hotlist**,
  כך שרוכשים לא ממשיכים לקבל מיילים של "בוא תקנה"

### איך זה מגיע לרב מסר

הפונקציה מוסרת ל-Webhook של תרחיש Make בשם
**"קורס סוכני AI — לידים ורוכשים לרב מסר"** (מזהה 9679108, פעיל), ושם ראוטר
מפריד בין שני המסלולים:

| מסלול | תנאי | מה קורה |
|---|---|---|
| ליד | יש מייל ו-`stage` שאינו `purchase` | נרשם לרשימה **Agents AI - Digital Product** (114908) |
| רכישה | יש מייל ו-`stage = purchase` | נרשם לרשימה **Agents AI - רוכשים** (114990), ואז חיפוש הכתובת ב-hotlist והוצאתה משם |

תנאי הליד מנוסח כ"כל מה שאינו רכישה" בכוונה: פנייה שתגיע בלי `stage` תיכנס
כליד במקום להיבלע בשקט. שלב החיפוש נחוץ כי האפליקציה מסירה מנוי לפי מזהה
ולא לפי כתובת מייל.

**האפליקציה הנכונה ב-Make היא Responder.live** ולא "Rav Messer / Responder"
הישנה. הראשונה מבקשת שדה אחד, User Token; השנייה מבקשת זוג מפתחות שהתמיכה
מנפיקה, וזה מה שתקע אותנו. את הטוקן לוקחים מרב מסר: הגדרות ← חיבורים
חיצוניים (API).

### המסלול הישיר (עדיין לא פעיל)

הפונקציה יודעת גם לדבר עם `api.responder.co.il` בעצמה, ונופלת לשם אם Make
לא זמין. זה דורש consumer key משלנו, שרב מסר טרם הנפיקו. מה שנבדק:
כותרת בלי `c_key` מוחזרת עם 400 "Invalid consumer key", ואילו `c_key` שאינו
מוכר גורם ל-500 עם גוף ריק — וה-Client ID ממסך "מפתח כללי לחשבון" מתנהג
בדיוק כמו מפתח מומצא. כלומר הוא שייך למערכת אחרת של רב מסר.

`/api/lead?selftest=1` (מוגן מאחורי `RAV_SELFTEST=1`) מריץ את כל וריאציות
האימות מול ה-API הישיר ומחזיר את התשובה של רב מסר לכל אחת, וגם את הרשימות
בחשבון עם המזהים שלהן כשהחיבור מצליח.

משתני סביבה (Vercel ← Settings ← Environment Variables):

| משתנה | למה |
|---|---|
| `MAKE_WEBHOOK_URL` | ה-Webhook של התרחיש. יש ברירת מחדל בקוד |
| `RAV_U_KEY` / `RAV_U_SECRET` | זוג החשבון מהתמיכה (03-7177777) |
| `RAV_CLIENT_ID` / `RAV_CLIENT_SECRET` / `RAV_USER_TOKEN` | ממסך "מפתח כללי לחשבון" |
| `RAV_LIST_HOTLIST` / `RAV_LIST_BUYERS` | מזהי הרשימות, למסלול הישיר |
| `RAV_SELFTEST` | `1` בזמן הגדרה בלבד |

דיבוג: הלוגים של הפונקציה נמצאים ב-Vercel תחת Deployments ← Functions.

## העלאה ל-Vercel

הריפו מוכן לדיפלוי כמו שהוא, בלי שלב build. `vercel.json` כבר מגדיר
כתובות נקיות (`/thanks` במקום `/thanks.html`) וקאשינג לפונטים.

1. vercel.com ← Add New ← Project ← מייבאים את `ronbs4896/ron-amit-claude`
2. Framework Preset: **Other**. לא נוגעים בשום הגדרת build. Deploy.
3. אם העבודה עדיין בברנץ' ולא ב-main: Settings ← Git ← Production Branch ←
   בוחרים את הברנץ' של העבודה
4. אצל Morning: כתובת ההפניה אחרי תשלום מוצלח ← `https://הדומיין/thanks`

קישור ישיר לתקנון: `/#takanon` פותח את המודאל אוטומטית.
